# NICRoute

Windows 10 / 11 x64 中文网卡分流工具。使用 WPF 桌面界面管理 sing-box TUN 引擎，不需要目标应用支持代理。

## 使用

解压 `NICRoute-win-x64.zip`，运行其中的 `NICRoute.exe`。独立运行包自带 .NET；请保留整个目录，尤其是 `engine` 文件夹。

1. 选择**全局默认网卡**。没有应用规则的流量使用这个出口；也可以选择 Windows 自动选择。
2. 点击**添加应用**：默认从当前用户安装的 Windows 应用（UWP / Microsoft Store / MSIX）按名称选择；普通程序可以浏览 exe 文件。
3. 为应用选择首选网卡，设置回退为**不联网**、**全局默认**或**其他网卡**。
4. 点击**保存并应用**，再点击**启动分流**。启动虚拟网卡需要 UAC 管理员授权。
5. 最小化后驻留通知区域；关闭窗口会停止分流并退出。停止后恢复 Windows 自身路由。

### 管理已配置应用

默认打开“已配置应用”，集中显示所有应用的首选网卡、回退方式、出口和启用状态。支持按名称、exe 路径或应用包名搜索，按 Windows 应用/桌面程序、已启用/已停用筛选；可逐项编辑、启停、删除，或勾选当前列表中的应用批量操作。筛选隐藏的项目不会参与批量操作，删除前会提示确认。

新增或编辑后会定位到对应规则，也可从托盘菜单“管理已配置应用”返回。修改需点击“保存并应用”后生效，管理页会提示待保存状态；已停用或删除规则的应用使用全局默认出口。规则沿用原有配置文件，升级后无需重新添加。

### 每网卡流量监控（0.2.2 起）

网卡卡片显示实时上行、下行速率；“流量监控”页统一列出所有网卡的速率及本次打开软件后的累计收发量。每秒在后台读取 Windows 接口字节计数，用实际采样间隔计算速率，支持 64 位计数，无需启动分流或授予管理员权限。

统计范围为整张网卡，包含其他应用、局域网和后台流量；不是单个应用的用量，也不是运营商账单。物理网卡与虚拟网卡可能记录同一份流量，因此不把各网卡简单求和。累计从首个有效采样开始，退出后清零；读取失败或计数器重置期间不估算缺失流量。首次采样、网卡重连和长时间采样中断后显示“正在采样”，避免错误速率；断开显示 0，无法读取显示“—”。B/s、KiB/s、MiB/s 等为字节速率，1 KiB = 1024 B。

### 回退规则

| 场景 | 行为 |
| --- | --- |
| 首选网卡可用 | 使用首选网卡 |
| 首选不可用，回退为不联网 | 在本机拒绝该应用的新连接 |
| 首选不可用，回退为全局默认 | 使用全局默认的实际出口 |
| 首选不可用，回退为另一网卡 | 使用指定的备用网卡 |
| 备用网卡或指定的全局网卡也不可用 | 不联网，不再隐式回退 |
| 首选网卡恢复 | 自动切回；原有连接关闭，应用需重连 |
| 规则停用 | 应用跟随全局默认 |

网卡每 5 秒检测一次。默认以连接状态和可用 IP 判断；在“网络检测”中可开启绑定网卡的 TCP 目标检测，连续两次失败才回退，成功后恢复。目标 IP/端口可自定义，默认 `223.5.5.5:443`；它只能代表该目标的连通性，不代表全部互联网。

### Windows 应用支持

通过 `Get-AppxPackage` 和 `Get-StartApps` 读取当前用户安装且具有启动入口的应用，按显示名称选择。配置保存 Package Family Name，不要求用户填写 exe 路径。引擎使用版本无关的应用包目录表达式，覆盖该包中的可执行文件和辅助进程，匹配同一发布者的版本更新。

这不是 WFP Package SID 隔离：共享宿主进程、包外服务、代理代发和一些系统组件的流量可能无法归属于原应用，需为实际联网进程单独建规则。开发模式的非标准安装目录按原目录匹配。应用移动到其他磁盘后，点击保存会重新读取安装目录；应用更新到新包身份需要重新选择。

### 生效范围及注意事项

- 分流运行时接管普通路由的 IPv4 / IPv6 TCP 和 UDP，应用规则优先，全局出口兜底。系统全局出口只在分流运行时生效，不永久修改网卡 metric。
- Windows 的共享 DNS 服务（Dnscache）代表其他应用发起的 DNS 查询使用全局出口。能识别进程的 DNS 查询使用对应应用出口。DNS 服务器 IP 可配置，默认 `223.5.5.5`。
- 更改配置后必须保存并应用。未保存的草稿只改变界面预览，不影响当前流量。运行中重新应用会重启引擎，期间网络短暂恢复系统路由。自动网卡回退通过本机控制 API 切换，不重建 TUN。
- 新增/移除应用规则需要重新应用。新插入、改名的网卡若不在本次引擎配置中，也需重新应用。缺失网卡按不可用处理；规则不会偷偷改绑到另一张网卡。
- 已建立的连接不保证直接接管；启用后建议重新启动目标应用。回环、显式绑定其他物理接口绕过 TUN、内核产生和其他 VPN 提前接管的流量不属于可靠控制范围。不要与另一款 TUN/VPN 同时启用。
- **“不联网”是分流运行期间的连接策略，不是防泄漏防火墙。** 停止、退出、崩溃或重新应用期间不保证断网隔离。不提供持久化 kill switch。
- 本版本**没有限速功能**，上传/下载限速留作后续工作。

在目标应用中访问你信任的出口 IP 查询服务，并在“运行日志”核对进程路径及 `nic-*` 出口。局域网访问同样遵循应用规则，选定网卡必须具有到目的网络的路由。

## 软件自动更新（0.2.0 起）

“软件更新”页提供手动检查，默认在主界面可用 2 秒后自动检查一次。自动和手动入口共用进行中的检查；手动检查总有结果，且不会使用过期的已完成会话缓存。稳定版只检查稳定渠道，测试版选项同时检查稳定和测试渠道，并按整数版本代码选择更新。

下载使用 [MUDL-C](https://github.com/daxiaamu/mudl-c) 0.5.14，支持最多 16 个来源、32 个连接、镜像同时传输和续传。连接数可在界面调整。GitHub 官方下载地址优先，镜像只有在 Actions 中完整下载并核对 SHA256 后才进入备用列表，不要求凑齐固定数量。

发现可选更新后可跳过该版本、忽略或下载并重启。忽略后更新入口保留红点；手动检查仍可显示跳过的版本。没有静默替换或后台强行安装。更新前会保存当前规则、停止分流并退出，独立辅助进程再替换程序文件；写入失败或新版本未通过启动确认时尝试恢复原版本。配置保存在安装目录之外，更新不会重置。

**0.1.0 没有更新模块，需要手动安装一次 0.2.0。** 此后可在软件内更新。强制更新策略已支持，但当前 `maxForcedVersionCode` 为 0，不强制更新。

更新以 GitHub 官方 HTTPS 内容为信任根。元数据有 7 个入口；官方指针固定不可变清单的 SHA256，客户端拒绝策略回滚与同版本冲突。官方源不可用时只能复用未过期且已被官方确认的本地指针，不能由未经认证的镜像建立新更新。安装前再次校验整包 SHA256、包内每个文件、真实 PE 程序的应用标识/平台/版本代码；已安装版本有可信 Authenticode 签名时还要求签名发布者连续。当前构建未配置发行方代码签名，SHA256 本身不能替代签名。

更新设置与已接受策略保存在 `update-settings.json`。下载、备份、安装结果在配置目录的 `updates` 子目录；备份保留供排查。断电、系统崩溃、其他用户同时占用程序文件等情况仍可能需要手动恢复。详情及发版步骤见 [更新实现说明](docs/updates.md)。

## 配置与隐私

配置保存在 `%LOCALAPPDATA%\NICRoute\settings.json`，支持 JSON 导入/导出。网卡以稳定的接口 ID 保存。程序不设置开机自启，不安装后台服务，不上传配置、日志或遥测。连接日志仅在内存中保留最近 500 条，包含进程路径和目标地址。

运行时引擎配置在同目录 `runtime` 中，包含随机本机 API 密钥，停止后删除；不得作为普通配置导出。控制 API 和拒绝端点只绑定 `127.0.0.1`。引擎执行前验证 SHA256。

## 开发与构建

要求 Windows x64、.NET 10 SDK、PowerShell 7。没有第三方 NuGet UI 依赖。

```powershell
# 从官方 GitHub 下载固定版本引擎，并校验官方 release SHA256
.\scripts\Get-Engine.ps1

# 构建及策略/真实配置校验；生成依赖 .NET 10 桌面运行时的包
.\scripts\Build.ps1

# 生成包含 .NET 10.0.14 运行时的独立运行包
.\scripts\Build.ps1 -SelfContained

# 本机集成测试：使用 mixed 入站，不启动 TUN、不修改系统路由
dotnet run --project tests\NICRoute.Tests -c Release -- --engine "$PWD\engine\sing-box.exe" --integration --catalog

# 隔离目录中的真实更新进程：成功重启与失败回滚
.\scripts\Verify-Updater.ps1
```

运行包：`dist\NICRoute-win-x64\NICRoute.exe`，ZIP：`dist\NICRoute-win-x64.zip`。

框架依赖包：`dist\NICRoute-win-x64-framework`，要求已安装 .NET 10 Windows Desktop Runtime。SDK 10.0.100 或更高可用于编译，独立运行包固定在构建时核实的 10.0.14 运行时。

## 实现

- `src/NICRoute.Core`：配置存储、Windows 应用/网卡发现、纯回退策略、引擎配置、带认证的本机出口切换及进程生命周期。
- `src/NICRoute.App`：WPF 中文界面、规则编辑、托盘、UAC 重启、连通性检测及应用配置。
- `tests/NICRoute.Tests`：无测试框架依赖的策略矩阵、包版本匹配、配置检查及真实引擎本机集成测试；任一断言失败返回非零退出码。
- `src/NICRoute.Core/Updates`：共用检查会话、权威指针/清单、MUDL 适配、文件校验与更新事务。
- `src/NICRoute.Updater`：独立进程等待旧版本退出、替换文件、验证重启并在失败时回滚。
- `tools/NICRoute.UpdateTool`：从实际 PE 读取更新身份、生成完整文件清单、校验 Actions 输出。

数据路径：`应用 → TUN → 进程路径/包目录匹配 → 应用 selector → 绑定物理网卡的 direct 出口`。全局也有独立 selector。“不联网”selector 指向本机 SOCKS 拒绝端点，端点从不创建对外 socket。使用这一方式是因为 sing-box 1.13+ 已移除 block outbound，且 selector 不能指向路由 reject action。

每次网卡检测后只更新 selector；关闭已建立连接，避免旧连接继续留在原出口。运行中规则变更通过重启引擎应用。引擎在独立隐藏控制台中启动，通过 Ctrl+C 正常退出并清理 TUN；Job Object 保证管理程序异常退出时结束引擎，不遗留孤儿进程。

## 验证范围

已验证策略组合、包目录跨版本/发布者边界、导入校验、真实引擎配置、程序识别、拒绝和恢复以及正常进程退出。集成测试不创建 TUN。交付环境未进行真实系统 TUN、多网卡拔插和 Windows 应用联网的端到端验收，需在测试机进行：

1. 两张实际可上网网卡分别作为不同应用的出口，核对外部源地址。
2. 拔除首选网卡，依次检查三种回退；恢复后检查切回。
3. 同时拔除备用或全局网卡，检查不联网。
4. Windows 应用发起连接后检查进程目录；更新应用后重复。
5. 验证 IPv6、UDP/QUIC、共享 DNS、睡眠唤醒及停止后的路由/DNS恢复。
