本机当前只有一个公网默认路由，不能完成“两张网卡同时独立访问互联网”的完整双 WAN 验收。测试环境的公网域名会由本机网络层解析到 `198.18/15`，因此实际出口证据使用 PktMon 对各物理接口的目标报文计数，而不是外部 IP。

## 复现

隔离配置 `artifacts/tun-single-1g/profile`：

- 客户端 A：完整 exe 路径规则，首选 1G，回退不联网。
- 客户端 B：独立完整 exe 路径规则，首选 25G1，回退不联网。
- 全局默认：1G。
- 另一个原路径客户端不设规则，用于验证全局出口。

固定目标：`https://api.ipify.org`，本机解析为 `198.18.1.95`。

修复前，B 的 10 次请求全部成功。对唯一目标地址过滤后，PktMon 记录：

| 接口 | 出包 | 出字节 | 入包 | 入字节 |
| --- | ---: | ---: | ---: | ---: |
| 1G（组件 3） | 90 | 10,026 | 106 | 42,034 |
| 25G1（组件 15） | 0 | 0 | 0 | 0 |

由此确认进程规则已选择 25G1，但 Windows 仍沿 1G 默认路由外发，不是 DNS、selector 或规则预览错误。

## 修复验证

修复内容：

1. 每个 sing-box direct 网卡出口绑定该卡首个 IPv4/IPv6 源地址。
2. 为引擎安装动态 WFP 条件：源地址属于网卡 X 时，下一跳网卡必须也是 X；不一致则阻断。
3. WFP 建立失败时仍中止启动，不静默放行。
4. 启动时保存接口名称和首个 IPv4/IPv6 地址快照。运行中绑定条件变化时，selector 直接改为阻断并要求重新应用，避免 DHCP 新地址绕过启动配置。
5. 同一 IP 同时属于不同网卡时拒绝启动，地址归属明确后才建立约束。

最终 `dist/NICRoute-win-x64` 真机结果：

| 用例 | 结果 |
| --- | --- |
| B 连续 5 次访问目标 | 全部失败；目标在 1G/25G1 的出包计数均为 0 |
| A 访问目标 | 成功 |
| 未配置客户端使用全局 1G | 成功 |
| B 显式绑定 1G 地址绕过 | 失败 |
| 正常停止 | TUN 消失，默认路由恢复 1G |
| 动态 WFP 清理 | 应用规则 0，引擎出口规则 0 |
